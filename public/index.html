What a crypto mixer does

A crypto mixer takes a deposit of cryptocurrency and returns equivalent coins to a different address. The deposit and the payout are separate transactions. They do not share an input, an output, or a timestamp. The on-chain link between the sender and the receiver is broken. E operates this process for eight assets across twelve networks. The user supplies the payout address. The user sets the fee, the number of rounds, and the delay. No account is created. No identity is collected.

Supported assets and networks

BTC on Bitcoin. ETH on Ethereum, Base, Optimism and Aurora. USDT on Ethereum, BNB Chain, Polygon, Solana and TRON. USDC on Ethereum, BNB Chain, Polygon, Avalanche and Solana. BNB on BNB Chain. SOL on Solana. LTC on Litecoin. ZEC on Zcash. Each asset is bound to its networks. A deposit address is provided for each pair. The address format matches the network. USDT on TRON uses a T-address. USDT on Solana uses a Solana address. The network is selected before the deposit address is shown.

Fee and processing time

The fee is set by the user. The range is 0.1% to 1.5%. The default is 1%. The fee is deducted from the payout. The network fee is paid by E. The user selects the number of rounds, from 1 to 5. More rounds add separation between the deposit and the payout. The user selects the delay, from 0 to 72 hours. The payout is released after the delay. The deposit window is one hour. The countdown does not block the flow. If the window expires, the rate refreshes on the next interaction.

How the deposit address is used

The deposit address is shown when the user starts the flow. The address is shown in full, in a monospaced font, with no truncation. A QR code is rendered from the address. The copy button copies the address only, with no trailing space or newline. The network name is shown beside the address. A warning line states the asset and the network. The warning updates when the pair changes. The address is read from the selected pair at render time. A stale address from a previous pair does not survive a switch.

Privacy and retention

No account is created. No email is collected. No identity is checked. The payout address is supplied by the user. Session data is stored in browser storage. The data is cleared when the tab closes. No analytics scripts run. No tracking pixels load. No cookies are set. The only external request is to a price feed. Explorer links open with referrer suppressed. The content security policy blocks third-party scripts, third-party styles, and third-party fonts.
